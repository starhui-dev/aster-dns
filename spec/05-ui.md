# Web UI / UX

## 1. 技术

- SolidJS
- TypeScript strict
- Vite
- Tailwind CSS
- 组件保持 accessible，键盘操作可用
- API client 集中封装
- 所有请求支持 abort/cancellation
- 不在浏览器保存 Provider secret

## 2. App Shell

Desktop：

```text
┌────────────────────────────────────────────────────────┐
│ Topbar: global search / refresh / user                 │
├──────────────┬─────────────────────────────────────────┤
│ Dashboard    │                                         │
│ Zones        │              Content                    │
│ Accounts     │                                         │
│ Audit        │                                         │
│ Users*       │                                         │
│ Settings     │                                         │
└──────────────┴─────────────────────────────────────────┘
```

`Users` 仅 admin 可见。

## 3. Dashboard

展示真实、可操作的信息，不做装饰性 KPI：

- provider account healthy/unhealthy；
- total indexed zones；
- zone sync failures；
- recent DNS mutations；
- recent failed mutations；
- stale accounts；
- 快捷进入某 account/zone。

## 4. Provider Accounts

列表：

- display name；
- provider badge；
- enabled；
- credential configured；
- validation state；
- zone count；
- last validated；
- last synced；
- actions。

新增账号采用 drawer/dialog：

1. 选 Provider；
2. 根据 `credential_schema` 渲染字段；
3. non-secret options；
4. Save；
5. Validate；
6. Sync Zones。

已保存 secret 输入框永远不回填。修改凭据明确显示“替换凭据”。

## 5. Zones

支持：

- global search；
- provider filter；
- account filter；
- status filter；
- stale indicator；
- pagination/infinite loading；
- 显示来源 account；
- 打开 zone records；
- account/zone refresh。

不要按 provider 分成四套完全不同页面。

## 6. Record Table

默认列：

- Name
- Type
- Value/Entries summary
- TTL
- Routing/Line（存在时）
- Weight（存在时）
- Proxy（存在时）
- Status（存在时）
- Actions

一个 RRSet 有多个 entries 时可展开，不要把长 TXT/SRV 全部塞在单行。

页面顶部显示：

- zone name；
- provider/account；
- last fetched time；
- refresh；
- Add record；
- filter/search。

## 7. Record Editor

基础字段：

- Name（支持 @ UI shorthand）；
- Type；
- TTL；
- Entries；
- 根据 type 显示 value/priority/weight/port/target；
- 根据 capability 显示 Provider extensions。

类型切换要清理不兼容字段并要求确认，不能偷偷保留错误 payload。

提交前前端验证只是体验优化，后端必须重新验证。

## 8. Provider-specific Fields

前端从 API 获取 capability/field descriptor。

例：

- `supports_proxy=true` -> proxy toggle；
- `routing_line.options` -> line select；
- `supports_weight=true` -> weight input；
- read-only extension -> detail only。

只允许在集中的 renderer/adapter 中存在 provider-specific display customization；业务页面不能散落大量 provider string condition。

## 9. Destructive UX

单条删除：显示完整 record summary，明确确认。

批量删除：

- 显示数量；
- 显示 zone；
- 超过阈值时要求输入 zone name；
- 提交后显示逐项结果；
- 失败项可以复制安全错误信息；
- 禁止“全部成功” toast 掩盖 partial failure。

## 10. Conflict UX

出现 optimistic concurrency conflict：

- 不覆盖；
- 提示“记录已在其他位置发生变化”；
- 展示当前 Provider 值和用户准备提交的值；
- 提供 Reload / Reapply 按钮；
- Reapply 必须基于新 fingerprint 再提交。

## 11. Error UX

区分：

- account auth expired/invalid；
- permission denied；
- provider rate limit；
- provider timeout；
- validation；
- conflict；
- account disabled；
- stale cache fallback。

错误必须携带 request id 供排查，但不能暴露 raw signed provider request。

## 12. Auth UX

- 默认首先展示 Passkey 登录；
- 若管理员启用密码 fallback，再显示密码方式；
- TOTP 二次验证单独步骤；
- 用户设置页管理 Passkeys；
- 删除最后一个可用认证方式前阻止或要求先配置替代方式；
- session 列表可撤销其他会话。

## 13. Responsive

- < 768px sidebar 变 drawer；
- records table 转为横向滚动或 compact cards；
- mutation dialog 保持可用；
- 不要求移动端完成大规模批量编辑，但单条 CRUD 必须可用。

## 14. Accessibility

- dialog focus trap；
- label 与 input 关联；
- error aria-live；
- icon-only button 有 accessible name；
- 不仅靠颜色表达状态；
- 键盘能完成主要 CRUD。
